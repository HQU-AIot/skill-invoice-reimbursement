# 命名与目录规范

## 一、主档命名

```text
发票：{seq:02d}_{short}_{amount:.2f}元_发票{invoice_no}.pdf
订单：{seq:02d}_{short}_订单{order_amount:.2f}元_{order_no}{ext}
支付：{seq:02d}_{short}_支付{pay_amount:.2f}元_{order_no or date}.jpg
```

示例：

```text
01_电子元件A_13.25元_发票12345678901234567890.pdf
01_电子元件A_订单13.25元_1234567890123456789.png
01_电子元件A_支付13.25元_1234567890123456789.jpg
```

规则：

- `seq` 两位数字，最终连续 `01..N`。若 N ≥ 100，改用三位 `{seq:03d}`，并同步修改工作簿、交付夹和所有脚本中的序号宽度。
- `short` 简短稳定；同一物品多次购买用 A/B/C 或 1/2/3 区分。
- 金额两位小数。
- 订单号完整保留；文件名总长 ≤ 120 字符（Windows 路径上限更严格，根目录不要太深）。
- 同一订单多张截图：主图用标准名，补充图加 `_明细`、`_2`。
- 已取消订单、已退款订单不进入主档命名，放 `04_已取消订单`。

## 二、目录结构

```text
发票汇总/
├─ 财务报表.xlsx
├─ 发票核对报告.txt
├─ 支付截图待补清单.txt
├─ 截图齐全情况.txt
├─ 报销交付_YYYYMMDD/
├─ 01_电子发票/
│  └─ OFD与XML/
├─ 02_订单截图/
│  └─ 支付凭证/
├─ 03_新增待整理/
│  ├─ 电子发票/ 订单截图/ 支付截图/
│  ├─ 03_待确认/
│  ├─ 04_已取消订单/
│  └─ 放入说明.txt
├─ 04_未报销发票_待补材料/
│  ├─ 01_物品_金额/
│  ├─ ...
│  └─ 说明.txt
├─ 98_技术资料_与报销无关/
├─ 99_其他/
│  ├─ 不报销/
│  ├─ 重复发票/
│  ├─ 重复截图/
│  ├─ 原始压缩包/
│  └─ 历史待办_已解决/
└─ _原始备份_YYYYMMDD/
```

原则：

- 主档 `01`、`02` 只放已入表的材料。
- 待补、取消、额外支付、重复件、技术资料全部隔离。
- 与报销无关的技术资料（PCB、3D 模型、电路图、数据手册）放 `98_技术资料_与报销无关`，不要混进主档或交付夹。
- 每次新文件先放 `03_新增待整理` 的三个入口，处理完清空入口。
- 交付夹是副本，可整夹重建。

## 三、待补文件夹

```text
04_未报销发票_待补材料/
├─ 01_物品_金额/
│  ├─ 发票.pdf
│  ├─ 订单截图.png
│  ├─ 支付截图.jpg
│  └─ 缺什么.txt
├─ ...
└─ 说明.txt
```

`说明.txt` 顶层写清：

- 本文件夹是什么（未报销/待补，不计入合计）。
- 共几项、总金额。
- 每项缺什么、怎么补。
- 不删除、补后如何恢复。

## 四、交付文件夹

```text
报销交付_YYYYMMDD/
├─ 00-报销说明.txt
├─ 01-物品-发票.pdf
├─ 01-物品-详情.png
├─ 01-物品-支付.jpg
├─ ...
├─ NN-物品-发票-OFD转换件.pdf   # 可选
├─ NN-物品-XML信息页.pdf        # 可选
└─ 财务报表.xlsx
```

规则：

- 序号宽度与工作簿完全一致（默认两位；N ≥ 100 时统一三位）。
- 每个物品默认 3 个文件；多张订单截图用 `-详情2`。
- 保留原扩展名，不强制转换。
- 转换件后缀必须能看出是转换件，不能伪装成正式发票。
- 交付夹内工作簿必须是主档最新副本。
- `00-报销说明.txt` 写：张数、总额、命名规则、待补清单位置、报表结构。

## 五、报告命名

- `发票核对报告.txt`：完整核对报告。
- `支付截图待补清单.txt`：支付证据状态。
- `截图齐全情况.txt`：订单/支付四象限。
- `03_新增待整理/放入说明.txt`：新文件放哪里、编号进度、待办分类。

统一使用 UTF-8 with BOM + CRLF，Windows 记事本打开不乱码。
