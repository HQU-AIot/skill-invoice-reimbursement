# 常见坑与修复

## 1. Excel 锁文件

**现象**：`openpyxl.save` 报 `PermissionError: [Errno 13] Permission denied`。

**原因**：Excel 打开着目标文件，或存在 `~$文件名.xlsx` 锁文件。

**处理**：

1. 先保存到 `财务报表_更新.xlsx`。
2. 校验内容。
3. 检查 Excel 进程和打开的工作簿。
4. 如果 `Saved=True`，`Close(SaveChanges=False)` 后覆盖。
5. 如果 `Saved=False`（用户有未保存修改），先 `SaveCopyAs` 备份，再关闭覆盖，并告知用户备份位置。
6. 覆盖后重新打开新文件。

**最危险的衍生错误**：新版存成了 `_更新.xlsx`，却忘了替换主文件，交付夹里还是旧版。终审必须比较主档与交付副本的 MD5/合计。

## 2. 全角/半角标点

老发票：

```text
发票号码：1234...
价税合计（大写） 壹拾柒圆玖角 （小写）¥17.90
```

新发票：

```text
发票号码:1234...
价税合计(大写) ... (小写) ¥17.90
```

正则必须同时兼容 `[：:]`、`[（(]`、`[）)]`。

## 3. PDF 文本块顺序错乱

有的 PDF 文本层是“标签在前，数值在后”：

```text
合 计
价税合计（大写） （小写）
...
¥29.16 ¥3.79
叁拾贰圆玖角伍分 ¥32.95
```

不要因为正则提取不到就判定发票异常。用中文大写金额反查小写金额，或视觉核对。

## 4. 字符编码

- 写 txt 用 `encoding="utf-8-sig"`，换行用 `\r\n`。
- 生成 Python 脚本时避免中文弯引号 `“”` 进入代码字符串，会报 `SyntaxError: invalid character`。
- Windows 控制台默认 GBK，读文件显式指定编码。

## 5. 重复统计

`Path.glob("*")` 会把子文件夹也算进去。统计重复截图数量用：

```python
len([p for p in dir.rglob("*") if p.is_file()])
```

## 6. 同金额不同交易

同一天、同一金额的两笔支付不一定是同一笔。必须比对：

- 订单号
- 交易单号
- 收款方
- 支付时间（精确到分钟）

示例：某订单 27.00 元有 01-10 和 01-11 两笔，日期差一天，需要确认是否重复支付。

## 7. 订单状态

- “已取消”订单即使有发票也不能报销。
- 同金额可能同时存在一张取消单和一张有效单（如 SO20260101001 取消、SO20260101002 有效），必须按订单号区分。
- 已退款要保留退款记录。

## 8. 发票预览

票面写“发票号码：以实物为准”，或没有符合票种位数的有效号码 → 只是预览，不是正式发票，不能入账。

## 9. 缺税号

购买方只写单位名称、税号栏为空 → 发票不合规，必须重开。  
示例税号：`91110000XXXXXXXXXX`（按实际单位填写）。

## 10. 金额差异

- 发票比实付多 2.43 / 0.12：常见于红包、优惠券未开票。
- 不要默认“金额差不多就行”，必须精确到分。
- 处理方式：商家重开、红字冲销、或财务同意按实付报销并附说明。

## 11. OFD 转换

- `easyofd` 的 `read()` 必须 `fmt="path"`，否则把路径当 base64 报错。
- 转换件的文字层可能把税号拆成空格，不适合做机读主件。
- 保留平台下载的正式 PDF 为主件，OFD 转换件只作可视化副本。
- 转换后核对发票号、金额、购方三项。

## 12. XML 不是发票版面

XML 是结构化数据。转 PDF 只能生成“信息页”，必须标注“非发票原件”，不能替代正式发票。

## 13. 交付夹被手工修改

交付夹是生成物。手工改名后下次重建会丢失。所有修改应在主档和数据源做，然后重新生成交付夹。

## 14. 序号预留

不要为了“以后可能补进来”预留空号。最终交付序号必须连续 `01..N`；待补项用独立的“待补 01..M”编号，不占报销序号。

## 15. 财务报表过度注释

用户要的是可提交的报表，不是工作底稿。默认只保留：

- 序号、物品、用途、数量、价格
- 合计行

不要加备注列、说明行、待补表。核对过程放 `发票核对报告.txt`。

## 16. 备份命令把目录复制进自己

**错误写法**：

```bash
cd 发票汇总
cp -r . _原始备份_$(date +%Y%m%d)
```

会报 `cannot copy a directory, '.', into itself`，并留下一个空备份目录。

**正确写法**：先复制到同级目录，再移入项目：

```bash
cd ..
cp -r 发票汇总 "发票汇总_备份_tmp"
mv "发票汇总_备份_tmp" "发票汇总/_原始备份_$(date +%Y%m%d)"
```

## 17. 构建交付夹时支付路径为空

`payment_file` 为空字符串时，`root / ""` 得到项目根目录；如果不先判断“是否为空/是否文件”，`shutil.copy2` 会尝试复制整个目录，报 `PermissionError` 或 `IsADirectoryError`。

**修复**：构建前校验 `invoice_file`、`order_files`、`payment_file` 都是非空且 `is_file()`；不满足就记为问题并跳过，不要继续复制。发布版 `build_delivery.py` 已加固。

## 18. 终审只解析 PDF，图片发票被漏算

`check_delivery.py` 原实现只对 PDF 累加金额。如果某张发票是 PNG/JPG，脚本会把它的金额算作 0，导致“PDF 总额 ≠ manifest 总额”的假失败。

**修复**：只比较“成功解析的 PDF 金额”与“这些 PDF 对应的 manifest 金额”，对非 PDF/解析失败的发票单独给出警告，并要求人工核对。发布版已按此逻辑处理。

## 19. 去重 `--apply` 只移动 MD5 重复

`dedupe.py --apply` 只处理 MD5 完全相同的文件。两张文件不同、但发票号相同的副本只会被报告，不会自动移动。需要根据报告人工决定保留哪一份，通常保留 `01_电子发票/` 下的正式 PDF。

## 20. 序号超过 99 时的重命名切片

SKILL 中的两阶段重命名示例用 `p.name[4:6]` 取两位序号。`seq >= 100` 时会截断错误。超过 99 项时改用 manifest 驱动重命名，或把序号宽度改为三位（`{seq:03d}`），并同步修改所有切片位置。
