# 发票校验规则

## 一、六项硬校验

| # | 检查 | 通过条件 | 失败处理 |
|---|---|---|---|
| 1 | 金额勾稽 | `金额合计 + 税额合计 = 价税合计`，误差 ≤ 0.005 | 人工复核/联系商家 |
| 2 | 大写金额 | 中文大写换算值 = 小写价税合计 | 人工复核 |
| 3 | 发票号码 | 数电票 20 位；老版电子票 8/10/12 位；号码本身有效 | 无有效号码 → 不是正式发票 |
| 4 | 购买方 | 名称 = 预期单位名称，税号 = 预期税号（通过参数传入，不硬编码） | 缺税号/抬头错 → 重开 |
| 5 | 日期 | 开票日期与业务时间关系合理（后补开票常见；先开票后付款需说明） | 记录说明 |
| 6 | 明细 | 各行金额之和 = 金额合计；各行税额之和 = 税额合计 | 人工复核 |

## 二、两种常见版式

### 版式 A：常规

```text
合 计 ¥11.73 ¥1.52
价税合计（大写） 壹拾叁圆贰角伍分 （小写）¥13.25
```

正则：

```python
r"价税合计[（(]大写[)）].*?[（(]小写[)）]\s*[¥￥]\s*([0-9.]+)"
r"合\s*计\s*[¥￥]\s*([0-9.]+)\s*[¥￥]\s*([0-9.]+)"
```

### 版式 B：标签与数值分离

```text
合 计
价税合计（大写） （小写）
...
¥29.16 ¥3.79
叁拾贰圆玖角伍分 ¥32.95
```

这种版式无法用“大写…小写”直接取到金额。回退策略：

1. 提取页面中所有中文大写金额候选：`[零壹贰叁肆伍陆柒捌玖拾佰仟万亿圆元角分整]{4,}`。
2. 用中文金额解析器转成数字。
3. 在页面所有 `¥xx.xx` 中找与该数字相等的一个。
4. 如果仍失败，人工/视觉核对。

## 三、中文大写金额解析

```python
DIGITS = {"零":0,"壹":1,"贰":2,"叁":3,"肆":4,"伍":5,"陆":6,"柒":7,"捌":8,"玖":9}
UNITS = {"拾":10,"佰":100,"仟":1000}
BIG = {"万":10_000,"亿":100_000_000}

def cn_to_number(s: str) -> float:
    total = 0.0      # 已结算的 万/亿 部分
    section = 0.0    # 当前小节
    number = 0.0
    for ch in s:
        if ch in DIGITS:
            number = DIGITS[ch]
        elif ch in UNITS:
            if number == 0:
                number = 1
            section += number * UNITS[ch]
            number = 0
        elif ch in BIG:
            section = (section + number) * BIG[ch]
            total += section
            section = 0
            number = 0
        elif ch in "圆元":
            total += section + number
            section = 0
            number = 0
        elif ch == "角":
            total += number * 0.1
            number = 0
        elif ch == "分":
            total += number * 0.01
            number = 0
        elif ch == "整":
            pass
    return round(total + section + number, 2)
```

测试用例：

```python
assert cn_to_number("壹拾柒圆玖角") == 17.90
assert cn_to_number("壹拾捌圆玖角") == 18.90
assert cn_to_number("叁拾贰圆玖角伍分") == 32.95
assert cn_to_number("壹佰肆拾壹圆贰角肆分") == 141.24
```

## 四、要素齐全性

一张可报销发票至少要有：

- 发票号码（数电票 20 位；老票 8/10/12 位）
- 开票日期
- 购买方名称 + 税号
- 销售方名称 + 税号
- 项目名称
- 金额、税额、价税合计
- 开票人

以下情况直接判“不合规”：

- 号码位数不符合票种，或号码明显无效（如“以实物为准”）
- 购买方税号为空
- 购买方名称不是单位名称
- 票面写“发票号码以实物为准”/“预览”
- 金额勾稽不平
- 大写与小写不一致

## 五、订单/支付匹配校验

### 金额

- 发票价税合计 = 订单实付 = 支付金额。
- 订单实付不是商品原价：要扣除优惠券、红包、淘金币、满减。
- 支付金额要精确到分，不能四舍五入。

### 数量/规格

- 逐项比对，不能只看总额。
- 单位不同（套 vs 个）且金额一致 → 可备注说明。
- 规格/数量不一致 → 必须确认或重开。

### 日期

- 支付日期 ≤ 开票日期（后补开票正常）。
- 支付日期与订单下单日期一般同日或次日。
- 同一金额、相差一天的支付，要确认是否重复支付。

### 状态

- 订单“已取消/已退款” → 不报销。
- 支付“已退款” → 不报销。
- 支付“支付成功”但无订单 → 待确认。

## 六、分类矩阵

| 发票 | 订单 | 支付 | 金额 | 规格/数量 | 结论 |
|---|---|---|---|---|---|
| 合规 | 有 | 有 | 一致 | 一致 | 可报销 |
| 合规 | 有 | 有 | 一致 | 不一致 | 待补/确认 |
| 合规 | 有 | 有 | 不一致 | 一致 | 待补/重开 |
| 合规 | 有 | 无 | — | — | 待补支付 |
| 合规 | 无 | 有 | 支付=发票 | — | 待补订单 |
| 合规 | 无 | 无 | — | — | 待补订单+支付 |
| 预览/缺税号 | — | — | — | — | 不合规，重开 |
| 合规 | 已取消 | — | — | — | 不报销 |
| 用户明确不报 | — | — | — | — | 不报销 |

## 七、重复判定

- 文件级：MD5 完全相同。
- 发票号级：号码相同，即使文件不同。
- 保留规则：保留主档中的正式 PDF；副本移到 `99_其他/重复发票/`。
- 截图重复：同一订单/支付的另一张截图，移到 `99_其他/重复截图/`。
- 统计重复数量时只数文件，不要用 `glob("*")` 把子文件夹算进去。

## 八、常见金额差异

| 差异 | 常见原因 | 处理 |
|---|---|---|
| 发票比实付多几角/几元 | 红包、优惠券未体现在发票 | 让商家重开，或按实付报销并附说明 |
| 发票比实付少 | 运费未开票/部分开票 | 确认是否另有发票 |
| 发票金额=商品价，未含运费 | 运费单独开票或未开 | 找运费发票 |
| 多张发票合计=订单实付 | 拆票 | 合并核对 |

## 九、脚本自动校验的边界

`scripts/parse_invoice.py` 自动完成：

- 金额勾稽、大小写一致、发票号码位数、购方税号是否出现在票面。
- 传入 `--buyer-name` 时，额外校验购方名称是否出现在票面。
- 不传预期值时不校验抬头，只记录提取结果。

以下必须人工/视觉核对：

- 明细行金额、税额逐行加总是否等于合计（脚本只取票面“合计”行）。
- 购买方名称与税号的对应关系（脚本按“预期值是否出现在票面”判断）。
- 开票日期与订单付款日期的先后。
- 图片型 PDF / 截图发票的全部字段。
- 备注中的订单号是否真实对应该笔订单。
