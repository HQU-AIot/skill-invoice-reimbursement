# 演示视频脚本

目标：用 3–5 分钟让观众看懂 **“一堆发票/订单/支付截图 → 一个可交付的报销包”**，并愿意去 GitHub 试用。

建议成片 **4 分钟左右**，1080p，16:9。下面给出分镜、旁白、屏幕文字、命令和脱敏清单，可以照着录。

---

## 1. 视频信息

| 项 | 建议 |
|---|---|
| 时长 | 3–5 分钟（推荐 4:00） |
| 分辨率 | 1920×1080，30 fps |
| 比例 | 16:9 |
| 编码 | H.264 / AAC，MP4 |
| 大小 | ≤ 50 MB（GitHub 单文件建议） |
| 语言 | 中文旁白 + 中文字幕 |
| 风格 | 屏幕录制 + 少量标题卡；不要花哨转场 |
| 背景音乐 | 低音量，不抢旁白；可无 |

## 2. 录制前准备

强烈建议用 **虚构数据**，不要用真实票据。准备一个 `演示/` 目录：

```text
演示/

│  ├─ 02_传感器B_28.80元_发票12345678901234567891.pdf
│  ├─ 03_开发板C_99.00元_发票12345678901234567892.pdf
│  └─ 04_测试仪器B_199.00元_发票12345678901234567893.pdf   # 待补示例
├─ 02_订单截图/
│  ├─ 01_电子元件A_订单13.25元_1234567890123456789.png
│  ├─ 02_传感器B_订单28.80元_2234567890123456789.png
│  ├─ 03_开发板C_订单99.00元_SO20260118001.png
│  └─ 支付凭证/
│     ├─ 01_电子元件A_支付13.25元_1234567890123456789.jpg
│     ├─ 02_传感器B_支付28.80元_2234567890123456789.jpg
│     └─ 03_开发板C_支付99.00元_SO20260118001.jpg
├─ 03_新增待整理/
│  └─ 电子发票/04_测试仪器B_重复.pdf
├─ manifest.json
└─ 财务报表.xlsx
```

说明：

- 3 个完整项目 + 1 个待补项目，能演示“入表/待补”的区别。
- 第 4 项故意缺订单，演示 `PROBLEMS` 或待补文件夹。
- 可以用 PDF 编辑器生成一张版式简单的“示例发票”，全部字段虚构。
- 截图可以用图片编辑器做，金额与 manifest 一致即可。

## 3. 分镜表

### 0:00–0:15 开场钩子

**画面**：左边一个乱文件夹（几十个文件，名字混乱），右边一个整洁的交付夹（`01-物品-发票/详情/支付`）。

**屏幕文字**：

```text
一堆发票 + 订单截图 + 支付截图
↓
一个能交财务的报销包
```

**旁白**：

> 发票、订单截图、支付截图混在一个文件夹里，金额差几毛、文件名重复、还缺支付凭证。这个视频演示怎么把它们整理成一份可以直接交财务的报销包，并且每一分钱都对得上。

---

### 0:15–0:35 痛点

**画面**：快速切三个特写：

1. 发票金额 13.25，订单实付 12.80（红包）。
2. 同一张发票三个文件名。
3. 交付夹里发票、详情、支付数量对不上。

**屏幕文字**：

```text
金额不一致 · 重复件 · 缺证据链
```

**旁白**：

> 报销最怕的不是贴票，是这三件事：发票金额和实付对不上；同一张票下载了三次；交付时少了一张支付截图。人工核对，很容易漏。

---

### 0:35–0:55 它是什么 + AI 怎么调用

**画面**：展示 `README.md` 的“AI 怎么调用这个 Skill”章节，然后切到 Agent 对话框，输入：

```text
使用 invoice-reimbursement 整理 D:\demo\发票汇总。
购买方：示例单位；税号：91110000XXXXXXXXXX。
先备份，再解析、去重、匹配，生成财务报表和交付夹，最后终审。
```

**屏幕文字**：

```text
自动触发：整理发票 / 核对金额 / 缺哪些截图
显式调用：/invoice-reimbursement
         $invoice-reimbursement
```

**旁白**：

> 这是一个 Agent Skill，不是双击运行的软件。你在对话框里说“整理发票”“核对金额”，客户端会用 SKILL.md 的描述匹配意图，自动加载这套流程；也可以显式输入 `/invoice-reimbursement` 或 `$invoice-reimbursement`。加载后，Agent 读规则、调用脚本，做三层核对：发票本身合规；发票对得上订单和支付；每一张交付的发票都有完整证据链。不合规的隔离，缺材料的待补，重复的查重，最后逐字节终审。

---

### 0:55–1:20 安装与目录

**画面**：终端。

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

然后切到文件管理器，展示目录结构。

**屏幕文字**：

```text
01_电子发票 / 02_订单截图 / 03_新增待整理 / 04_待补 / 99_其他
```

**旁白**：

> 安装很简单：Python 3.10 以上，装两个依赖；OFD 再加一个可选包。目录分成主档、待整理、待补、隔离区。新文件先放 `03_新增待整理`，处理完再进主档。

---

### 1:20–1:55 解析发票

**画面**：终端执行解析命令，输出 3 个 `[OK]`、1 个 `[REVIEW]`。

```bash
python scripts/parse_invoice.py 01_电子发票/*.pdf \
  --buyer-name "示例单位" \
  --buyer-tax-id "91110000XXXXXXXXXX" \
  --json invoices.json
```

**屏幕文字**：

```text
金额勾稽 · 大小写 · 号码位数 · 购方税号
```

**旁白**：

> 解析器会提取发票号、日期、购方、销方、金额、税额、价税合计。它自动做四项检查：金额加税额等于价税合计；中文大写等于小写；号码位数符合票种；购方税号出现在票面。任何一项不过，就标记为需要人工复核。

**特写**：`checks` JSON，指出 `arithmetic: true`、`uppercase: true`。

---

### 1:55–2:25 去重

**画面**：终端执行：

```bash
python scripts/dedupe.py --root .
```

输出：

```text
duplicate file groups: 1 (1 extra copies)
duplicate invoice-number groups: 1 (1 extra copies)
```

**屏幕文字**：

```text
MD5 完全相同 → 重复文件
不同文件、同一发票号 → 同一张票的副本
```

**旁白**：

> 去重查两种：文件级 MD5，和发票号级。默认只报告，不删不改。确认后可以用 `--apply` 把 MD5 重复件移到隔离区；同号不同文件的副本会提示你人工处理，避免误删。

---

### 2:25–3:00 manifest 与交付夹

**画面**：快速展示 `manifest.json`（高亮 `seq`、`amount`、三个文件路径），然后执行：

```bash
python scripts/build_delivery.py \
  --manifest manifest.json \
  --out 报销交付_20260115 \
  --workbook 财务报表.xlsx
```

输出：

```text
items=3 invoice=3 detail=3 payment=3 extra=1
OK
```

**屏幕文字**：

```text
manifest = 唯一数据源
交付夹 = 可重建的副本
```

**旁白**：

> 所有数据集中在一个 manifest：序号、物品、金额、发票号，以及发票/订单/支付三个路径。交付夹从 manifest 生成，命名统一成“序号-物品-发票/详情/支付”。它是副本，随时可以重建，不要手工改。

---

### 3:00–3:30 报表与报告

**画面**：打开 `财务报表.xlsx`，展示五列 + 合计行；再打开 `发票核对报告.txt`，滚动到“问题清单”。

**屏幕文字**：

```text
财务报表：只放已报销
核对报告：问题、待补、全量明细
```

**旁白**：

> 财务报表默认极简：序号、物品、用途、数量、价格，加一行合计。待补、不报销、重复件不塞进表里，全部放在报告和对应文件夹。这样财务拿到的是一张干净的明细，不是工作底稿。

---

### 3:30–4:00 终审

**画面**：终端执行：

```bash
python scripts/check_delivery.py \
  --manifest manifest.json \
  --delivery 报销交付_20260115 \
  --workbook 财务报表.xlsx \
  --buyer-name "示例单位" \
  --buyer-tax-id "91110000XXXXXXXXXX"
```

输出：

```text
items=3 invoice=3 detail=3 payment=3
verified invoice total OK: 141.05
workbook data_rows=3 total=141.05
RESULT: PASS
```

**屏幕文字**：

```text
序号 · 三件套 · MD5 · PDF 金额 · 工作簿合计
```

**旁白**：

> 最后一步终审：序号是否连续；每个序号是否都有发票、详情、支付；交付件和主档是否逐字节一致；每张 PDF 的发票号和金额是否对得上；工作簿行数和合计是否正确。全部通过才 PASS。

**屏幕文字**：

```text
github.com/HQU-AIot/skill-invoice-reimbursement
```

## 5. 命令清单（可复制）

```bash
# 安装
python -m pip install -r requirements.txt
```

## 10. 常见录制问题

| 问题 | 处理 |
|---|---|
