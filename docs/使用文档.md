这份文档写给第一次用这套流程的人。目标：**把一个混着发票、订单截图、支付截图的文件夹，整理成可以直接交财务的报销包。**

技术细节见 [`技术文档.md`](技术文档.md)；Agent 的触发规则见 [`../SKILL.md`](../SKILL.md)。

## 适用对象与前置条件

适合：

- 需要把淘宝/天猫/拼多多/京东/立创/嘉立创等平台的电子发票整理成报销包。
- 发票、订单截图、支付截图混在一个文件夹里。
- 需要向财务说明“哪些能报、哪些缺材料、为什么”。
- 需要连续编号、统一命名、可复核的交付文件夹。

不适合：

- 只识别单张图片。
- 只做发票真伪查验。
- 只做记账凭证。

前置条件：

- Python 3.10+。
- 能运行命令行（Windows 可用 Git Bash / PowerShell）。
- 有权限读写项目文件夹。

> 本文命令按 Git Bash 编写（`*.pdf` 由 shell 展开）。PowerShell 不支持同样的通配符展开，需要把文件列表显式传给 `parse_invoice.py`，或使用 `Get-ChildItem` 管道。

把整个仓库复制到 Agent 客户端的 skills 目录：

```bash
# ZCode / 通用 agent skills
cp -r invoice-reimbursement ~/.agents/skills/
```

也可以放在项目的 `.zcode/skills/` 或客户端支持的插件目录。核心是保留：

```bash
python -m pip install -r requirements.txt
```

## 5 分钟快速开始

下面用一个小目录跑通“解析 → 构建 → 终审”。示例中的文件名可以换成你自己的。

### 第 1 步：准备目录

```bash
mkdir -p 演示/01_电子发票
mkdir -p 演示/02_订单截图/支付凭证
```

放入：

- 一张正式发票 PDF → `演示/01_电子发票/`
- 一张订单截图 → `演示/02_订单截图/`
- 一张支付截图 → `演示/02_订单截图/支付凭证/`

### 第 2 步：解析发票

```bash
python scripts/parse_invoice.py 演示/01_电子发票/*.pdf \
  --buyer-name "你的单位名称" \
  --buyer-tax-id "你的单位税号" \
  --json 演示/invoices.json
```

看输出：

- `[OK]`：金额勾稽、大小写、号码位数、购方税号都通过。
- `[REVIEW]`：至少一项没过，先人工看 `invoices.json` 里的 `checks`。

### 第 3 步：写 manifest

在 `演示/` 下新建 `manifest.json`：

```json
{
  "buyer": {"name": "你的单位名称", "tax_id": "你的单位税号"},
  "items": [
    {
      "seq": 1,
      "short": "电子元件A",
      "item": "电子元件A 型号X1",
      "purpose": "样品测试",
      "qty": 1,
      "amount": 13.25,
      "invoice_no": "12345678901234567890",
      "invoice_date": "2026-01-15",
      "seller": "示例电子科技有限公司",
      "order_no": "1234567890123456789",
      "order_amount": 13.25,
      "invoice_file": "01_电子发票/01_电子元件A_13.25元_发票12345678901234567890.pdf",
      "order_files": ["02_订单截图/01_电子元件A_订单13.25元_1234567890123456789.png"],
      "payment_file": "02_订单截图/支付凭证/01_电子元件A_支付13.25元_1234567890123456789.jpg",
      "status": "complete",
      "note": ""
    }
  ]
}
```

字段说明见 [`../references/manifest-schema.md`](../references/manifest-schema.md)。关键约束：

- `seq` 从 1 开始，连续。
- `amount = order_amount`。
- 三个文件路径都存在，且是文件。
- `status` 为 `complete` 才进报销表。

### 第 4 步：生成交付夹

```bash
python scripts/build_delivery.py \
  --manifest 演示/manifest.json \
  --out 演示/报销交付_YYYYMMDD
```

预期输出：

```text
built .../演示/报销交付_YYYYMMDD
items=1 invoice=1 detail=1 payment=1 extra=0
OK
```

如果出现 `PROBLEMS:`，按提示补文件或改 manifest。

### 第 5 步：终审

```bash
python scripts/check_delivery.py \
  --manifest 演示/manifest.json \
  --delivery 演示/报销交付_YYYYMMDD \
  --buyer-name "你的单位名称" \
  --buyer-tax-id "你的单位税号"
```

看到：

```text
RESULT: PASS
```

即通过。`WARN` 不影响 PASS，但要看。

## 完整流程（10 步）

下面是正式整理一批材料的顺序。建议第一次完整走一遍，之后再按“新增一批”的简化流程处理。

### 第 0 步：备份与清点

```bash
# 在项目目录内执行
cd ..
cp -r 发票汇总 "发票汇总_备份_tmp"
mv "发票汇总_备份_tmp" "发票汇总/_原始备份_$(date +%Y%m%d)"
cd 发票汇总
```

统计：

```bash
find . -type f \( -iname '*.pdf' -o -iname '*.ofd' -o -iname '*.xml' \) | wc -l
find . -type f \( -iname '*.jpg' -o -iname '*.png' -o -iname '*.jpeg' \) | wc -l
```

把新文件放进：

```text
03_新增待整理/电子发票/
03_新增待整理/订单截图/
03_新增待整理/支付截图/
```

ZIP 先解压到临时目录，原 zip 放 `99_其他/原始压缩包/`。

### 第 1 步：解析发票

- PDF：`python scripts/parse_invoice.py ...`
- OFD：先 `easyofd` 转 PDF（见下文“OFD/XML”）。
- XML：直接读字段。
- 图片：视觉读取，逐项记录。

一次解析后存 JSON，不要反复手抄。

### 第 2 步：校验发票

六项：

1. 金额 + 税额 = 价税合计。
2. 大写 = 小写。
3. 发票号码位数符合票种（数电票 20 位，老票 8/10/12 位）。
4. 购买方名称 + 税号正确。
5. 开票日期与业务时间关系合理。
6. 明细金额/税额与合计一致。

任何一项不过 → 标记待人工复核，不要直接入表。

### 第 3 步：去重

```bash
python scripts/dedupe.py --root .
```

看报告：

- `duplicate file groups`：MD5 相同的文件。
- `duplicate invoice-number groups`：不同文件但发票号相同。

处理：

- MD5 重复：保留主档一份，其余移到 `99_其他/重复发票` / `重复截图`。
- 同号不同文件：人工决定保留哪份（通常保留 `01_电子发票/` 下的正式 PDF）。

需要自动移动 MD5 重复件：

```bash
python scripts/dedupe.py --root . \
  --apply --quarantine-dir 99_其他/重复发票
```

注意：`--apply` 不会移动“同号不同文件”的副本，脚本会提示。

### 第 4 步：匹配订单与支付

对每张发票：

1. 先看发票备注里的订单号。
2. 用订单号找订单截图。
3. 用金额 + 日期 + 收款方找支付截图。
4. 同金额多笔时，用订单号/交易单号排除。

核对：

- 发票价税合计 = 订单实付 = 支付金额（精确到分）。
- 数量/规格/品名一致。
- 订单状态不是“已取消/已退款”。
- 支付状态不是“已退款”。

### 第 5 步：分类处置

按矩阵决定去向：

| 情况 | 去向 |
|---|---|
| 发票 + 订单 + 支付 + 金额/规格一致 | 报销表 |
| 金额一致，数量/规格/品名不一致 | 待补 |
| 发票金额 ≠ 实付 | 待补 |
| 有发票 + 支付，缺订单 | 待补 |
| 有发票，缺订单和支付 | 待补 |
| 只有发票预览 | 待补 |
| 缺税号/抬头错 | 待补 |
| 订单已取消 | `03_新增待整理/04_已取消订单` |
| 用户明确不报 | `99_其他/不报销` |
| 额外支付，无发票/订单 | `03_新增待整理/03_待确认` |

每个待补项一个文件夹，写 `缺什么.txt`：

```text
是什么：物品名称、数量
金额：xx.xx 元
发票号：xxxxxxxxxxxxxxxxxxxx
开票日期：2026-xx-xx
销售方：xxx
订单号：xxx

已有（都在本文件夹）：
- 发票.pdf
- 订单截图.png
- 支付截图.jpg

缺什么：xxx
说明：xxx
怎么补：xxx
状态：已从报销表剔除，补齐后即可入表。
```

### 第 6 步：编号与命名

最终序号必须 `01..N` 连续。命名：

```text
{seq:02d}_{short}_{amount:.2f}元_发票{invoice_no}.pdf
{seq:02d}_{short}_订单{order_amount:.2f}元_{order_no}{ext}
{seq:02d}_{short}_支付{pay_amount:.2f}元_{order_no or date}.jpg
```

重命名用两阶段：

```python
tmp = []
for old, new in mapping.items():
    for p in root.glob(f"{old:02d}_*"):
        t = p.with_name("TMPRENAME_" + p.name)
        p.rename(t)
        tmp.append((t, new, p.name))

for t, new, old_name in tmp:
    rest = old_name.split("_", 1)[1]
    t.rename(t.with_name(f"{new:02d}_{rest}"))
```

改完同步 manifest 中的路径。

### 第 7 步：生成财务报表

默认极简：

- 一张 `报销明细` 表。
- 五列：序号、物品、用途、数量、价格。
- 只放已报销项目，序号 `01..N`。
- 最后一行合计。
- 不加备注列、说明行、待补表。

格式：

- 金额 `¥#,##0.00`。
- 表头深色底白字，细边框，隔行浅色。
- 冻结表头，自动筛选，打印一页宽。

生成后回读校验：单表、行数、序号、合计。

### 第 8 步：生成文本报告

四份，UTF-8 with BOM + CRLF：

- `发票核对报告.txt`
- `支付截图待补清单.txt`
- `截图齐全情况.txt`
- `03_新增待整理/放入说明.txt`

所有数字从数据计算，不手写。改完数据后重新生成整份报告。

### 第 9 步：生成交付夹

```bash
python scripts/build_delivery.py \
  --manifest manifest.json \
  --out 报销交付_YYYYMMDD \
  --workbook 财务报表.xlsx
```

交付夹结构：

```text
报销交付_YYYYMMDD/
├─ 00-报销说明.txt
├─ 01-物品-发票.pdf
├─ 01-物品-详情.png
├─ 01-物品-支付.jpg
├─ ...
├─ 财务报表.xlsx
```

`00-报销说明.txt` 由 Agent 生成（当前脚本不自动写），内容：总张数、总金额、命名规则、待补清单、报表位置。

### 第 10 步：终审

```bash
python scripts/check_delivery.py \
  --manifest manifest.json \
  --delivery 报销交付_YYYYMMDD \
  --workbook 财务报表.xlsx \
  --buyer-name "你的单位名称" \
  --buyer-tax-id "你的单位税号"
```

通过标准：

- `RESULT: PASS`，无 ERROR。
- 序号连续。
- 发票数 = 支付数 = 物品数。
- 每个序号都有发票/详情/支付。
- MD5 一致。
- 工作簿行数/合计一致。

WARN 要逐条看，尤其是“非 PDF 发票未机读”“解析失败”。

## 常见场景

### 场景 1：第一次整理一个文件夹

1. 先备份。
2. 把文件分成三类（发票/订单/支付），放进 `03_新增待整理`。
3. 解析、校验、去重。
4. 建 manifest。
5. 匹配、分类、编号。
6. 生成工作簿、报告、交付夹。
7. 终审。

不要一上来就改名；先把证据链理顺。

### 场景 2：新增一批发票

1. 新文件放 `03_新增待整理`。
2. 从当前最大序号 + 1 开始编号（不预留空号）。
3. 更新 manifest，`seq` 重排为 `1..N`（如果中间插入了新项）。
4. 重新生成工作簿、报告、交付夹。
5. 终审。

### 场景 3：只核对金额，不整理

```bash
python scripts/parse_invoice.py 01_电子发票/*.pdf \
  --buyer-name "你的单位名称" \
  --buyer-tax-id "你的单位税号" \
  --json invoices.json
```

看 `results` 里的 `total`、`amount`、`tax`、`checks`。再用 Excel 或脚本对订单/支付金额做三方比对。

### 场景 4：交付前最后审查

1. 确认工作簿是主档最新版（不是 `_更新.xlsx`）。
2. 跑 `check_delivery.py`。
3. 逐张 PDF 重新解析，金额总和 = 工作簿合计。
4. 看报告里的张数/总额/待补金额是否一致。
5. 确认待补项还在，未删除。
6. 确认备份完整。

### 场景 5：处理 OFD/XML

OFD：

```python
from easyofd import OFD

ofd = OFD()
ofd.read("发票.ofd", fmt="path")
open("发票_OFD转PDF.pdf", "wb").write(ofd.to_pdf())
```

- 必须 `fmt="path"`。
- 转换件放 `01_电子发票/OFD与XML/`，命名带 `OFD转换件`。
- 不要用转换件替代平台下载的正式 PDF。

XML：

- 直接读字段（发票号、购方、销方、金额、税额、明细）。
- 转 PDF 只能生成“信息页”，标注“非发票原件”。

### 场景 6：有重复发票

1. 跑 `dedupe.py --root .`。
2. MD5 重复：保留主档一份，其余移隔离区。
3. 同号不同文件：人工看哪份是正式 PDF；通常保留 `01_电子发票/` 下的。
4. 重新跑 dedupe，确认重复组为 0（隔离区会被跳过）。

### 场景 7：待补项补齐后恢复

1. 打开 `04_未报销发票_待补材料/01_物品_金额/缺什么.txt`。
2. 补齐缺失的订单/支付/重开发票。
3. 重新核对金额、数量、规格。
4. 把它加入 manifest 的 `items`，分配新序号（当前 `N+1`）。
5. 从待补文件夹移出，或保留副本并注明“已解决”。
6. 重新生成工作簿、报告、交付夹。

### 场景 8：用户明确不报

- 放 `99_其他/不报销/`。
- 在报告“排除项”里写清：物品、金额、原因。
- 不计入工作簿合计。
- 不要删除。

### 场景 9：一张订单多张发票

- 发票金额合计 = 订单实付。
- manifest 里可以拆成多个 `items`，但 `order_no` 相同，`order_amount` 只填一次或按分摊填。
- 交付夹里每张发票一个序号，订单截图可共用（复制多份或用 `-详情` 区分）。
- 报告里注明“拆票”。

### 场景 10：图片发票/截图发票

- 用视觉逐张读取，记录号码、日期、购方、税号、金额、税额、销售方、明细。
- 票面写“以实物为准” → 只是预览，不能报。
- 购方税号空白 → 不合规，重开。
- 图片发票在终审中不会被 PDF 解析器机读，`check_delivery.py` 会给 WARN；需要人工核对。

## 报表怎么看

### 财务报表.xlsx

默认只有 `报销明细`：

| 序号 | 物品 | 用途 | 数量 | 价格 |
|---|---|---|---|---|
| 01 | 电子元件A | 样品测试 | 1 | ¥13.25 |
| 02 | 传感器B | 样品测试 | 2 | ¥28.80 |
| 合计 | 2 张 | | | ¥42.05 |

- 只含已报销项目。
- 合计 = 各发票金额之和。
- 待补、不报销、重复件不在表里；看报告和对应文件夹。

### 发票核对报告.txt

建议结构：

1. TL;DR：张数、总额、可报销金额、待补数量。
2. 排除项（用户明确不报）。
3. 分批核对表。
4. 问题清单 P1..Pn。
5. 全量逐张核对表。
6. 检查方法与未做的检查。
7. 目录结构、命名规则、工作簿说明。
8. 建议处理顺序。
9. 附件索引。
10. 支付凭证核对表。

### 支付截图待补清单.txt

## 常见问题与排错

### Q1：`PermissionError: [Errno 13] Permission denied`（保存 Excel）

Excel 打开着目标文件。处理：

1. 先保存到 `财务报表_更新.xlsx`。
2. 校验内容。
3. 关闭 Excel（有未保存修改先 `SaveCopyAs` 备份）。
4. 覆盖主文件。
5. 重新打开。

最危险的衍生错误：新版存成了 `_更新.xlsx`，忘了替换主文件，交付夹里还是旧版。终审必须对比合计/MD5。

### Q2：`ModuleNotFoundError: No module named 'pdfplumber'`

```bash
python -m pip install -r requirements.txt
```

### Q3：`easyofd` 报 base64/UnicodeEncodeError

`read()` 必须加 `fmt="path"`：

```python
ofd.read("发票.ofd", fmt="path")
```

### Q4：报告打开乱码

用 `encoding="utf-8-sig"` 写，换行 `\r\n`：

```python
Path("报告.txt").write_text("\r\n".join(lines), encoding="utf-8-sig", newline="")
```

### Q5：`SyntaxError: invalid character '“'`

代码字符串里混入了中文弯引号 `“”`。改成英文 `"`，或把中文放在字符串内部。

### Q6：备份命令报 `cannot copy a directory into itself`

不要用：

```bash
cp -r . _原始备份_xxx
```

用：

```bash
cd ..
cp -r 发票汇总 "发票汇总_备份_tmp"
mv "发票汇总_备份_tmp" "发票汇总/_原始备份_$(date +%Y%m%d)"
```

### Q7：`build_delivery.py` 报 `missing payment: ... (empty)`

manifest 里 `payment_file` 为空。补齐支付截图路径，或把该项改成待补，不要让它以 `complete` 状态入表。

### Q8：终审报 `verified PDF total != manifest total for verified PDFs`

可能原因：

- 某张 PDF 金额与 manifest 不一致。
- PDF 是图片型，`pdfplumber` 读不到；看 WARN 里的“非 PDF/未解析”。
- manifest 金额写错。
- 交付夹里是旧版发票（MD5 不一致会单独报）。

逐张看 `check_delivery.py` 的输出，先解决 ERROR，再看 WARN。

### Q9：终审报 `detail count X != order_files Y`

交付夹里有多余的 `-详情N` 文件，或 manifest 的 `order_files` 少了。用 `--force` 重建交付夹，再检查 manifest。

### Q10：终审报 `workbook data rows X != items Y`

- 工作簿里有空行/标题行被算进去。
- 序号列不是数字（如 `"01"` 已兼容；如果是 `"1 "` 带空格，会被 `strip` 处理）。
- 工作簿不是最新版。
- 只读第一张表；如果数据在第二张表，检查会失败。

### Q11：终审报 `seq not contiguous`

manifest 的 `seq` 有空洞或重复。重排为 `1..N`，并同步文件名/工作簿/交付夹。

### Q12：去重后还有重复

- `--apply` 只移动 MD5 重复；同号不同文件不会自动移动。
- 隔离区/备份/交付夹会被跳过，重复报告里的路径可能不在主档。
- 处理完新文件后，把主档补齐，再跑一次。

### Q13：文件名太长 / 路径太深

- 文件名控制在 120 字符以内。
- Windows 默认 260 字符路径限制；把项目放在较浅的目录，或开启长路径支持。
- 订单号完整保留，但 `short` 要短。

### Q14：`--force` 删错了目录

`build_delivery.py --force` 会删除 `--out` 指定的目录。运行前确认路径；不要指向主档、备份或项目根目录。

### Q15：图片发票终审总是 WARN

这是预期行为：`pdfplumber` 不能读图片。用视觉核对发票号/金额/购方，并在报告中注明“图片发票，人工核对”。如果要求交付夹全部 PDF，加 `--require-pdf` 让非 PDF 发票直接 FAIL。

## 安全与隐私

- 脚本本地运行，不上传票据。
- 不要提交真实发票、截图、报表、manifest 到公开仓库。
- 演示/截图前模糊：单位名称、税号、发票号、订单号、姓名、电话、地址。
- `.gitignore` 已默认忽略票据和产出；仍建议发布前用 `git grep` 自查。
- 备份目录也包含敏感信息，不要上传。
